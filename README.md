# MentorLagbe — Server

REST API for the MentorLagbe tuition/mentorship platform. Built with **Express 5 + TypeScript + MongoDB + JWT + Stripe**. The Next.js client lives in a separate repository: [`mentor-lagbe-client`](https://github.com/Shakir4Mahmud/mentor-lagbe-client).

This service is designed to run as a long-lived process (Render, Railway, VM). It is **not** intended for Vercel serverless functions.

## Tech stack

| Layer | Technology |
|---|---|
| Runtime | Node.js (CommonJS) |
| Framework | Express 5 |
| Language | TypeScript (compiled to `dist/`) |
| Database | MongoDB Atlas via the official `mongodb` driver |

## Features

- Public tuition listing, filtering, detail view and public platform statistics.
- Student applications with duplicate checks, withdrawal and reviews.
- Tutor tuition CRUD, status control, applicant management and posting-usage stats.
- Student bookmarks (save/unsave/list).
- Admin user listing, role changes, tuition approval and transaction history.
- Role checks on every protected route; roles are read from MongoDB on each request.
- Stripe Checkout creation and payment verification for Pro plans.
- Health check endpoint for deployment monitoring.

## Environment variables

Copy `.env.example` to `.env` and fill in the values.

| Variable | Required | Description | Example |
|---|---|---|---|
| `PORT` | No | HTTP port (default `5000`) | `5000` |
| `MONGODB_URI` | Yes | MongoDB Atlas connection string | `mongodb+srv://user:pass@cluster.mongodb.net/MentorLagbe` |
| `CLIENT_URL` | Yes | Allowed CORS origin and Stripe redirect base | `http://localhost:3000` / Vercel URL |
| `JWT_SECRET` | Yes | Must match the client's `JWT_SECRET` | 64 random characters |
| `STRIPE_SECRET_KEY` | Yes | Stripe **test** secret key | `sk_test_…` |
| `STRIPE_CURRENCY` | No | `bdt` (default) or `usd` | `bdt` |

> `.env.example` is committed; real `.env` files are ignored.

## Authentication & roles

This API does **not** issue passwords or sessions. The Next.js client owns authentication via Better Auth.

1. The client signs a 1-hour JWT containing `{ email, name }` with the shared `JWT_SECRET` (`/api/token`).
2. The client sends it as `Authorization: Bearer <token>`.
3. `verifyToken` verifies the signature, looks the user up by email in MongoDB and populates `req.user` with the **current** `role` and `plan`.
4. Role middleware (`verifyStudent`, `verifyTutor`, `verifyAdmin`) then allows or rejects the request.

Because the role is read from the database on every request, changing a user's role takes effect immediately and cannot be forged by editing the JWT.

Roles: `student`, `tutor`, `admin`.

## Payments (Stripe test mode)

- Plans and prices are defined **server-side** in `src/routes/payment.routes.ts`:
  - `student` → **Pro Student**, 99 BDT (`1 USD`)
  - `tutor` → **Pro Tutor**, 499 BDT (`5 USD`)
- The client sends no amount; the server derives currency and price from `STRIPE_CURRENCY` and the user's role.
- Checkout metadata carries `userEmail`, `userRole` and `planName`.
- `success_url` → `<CLIENT_URL>/payment/success?session_id={CHECKOUT_SESSION_ID}`; `cancel_url` → `<CLIENT_URL>/payment/cancel`.
- Verification retrieves the session from Stripe, requires `payment_status === "paid"` and a metadata email matching the authenticated user, records the payment once (unique `stripeSessionId`, duplicate-key errors ignored) and sets the user's plan to `pro`.
- Keys and sessions are test-mode (`sk_test_…`, `cs_test_…`, `pi_…`). Test card: `4242 4242 4242 4242`.

> Limitation: there is no webhook. If the client never reaches the success page, plan activation is not automatic. Adding a webhook is the next recommended improvement.

## Database

Collections: `users`, `account`, `session`, `verification` (Better Auth), `tuitions`, `applications`, `payments`, `reviews`-related data inside `applications`.

Indexes include a unique `users.email`, `session.token`, `session.userId`, `account.userId`, `verification.identifier` and a unique partial `payments.stripeSessionId`.

> `npm run seed` is for a **fresh database only**. Do not re-run it on a populated database: it can duplicate tuitions and orphan existing applications.

## Deployment (Render)

1. Create a **Web Service** from this repository.
2. Runtime: **Node**. Build command: `npm install && npm run build`. Start command: `npm start`.
3. Add the environment variables from the table above. `CLIENT_URL` must be the exact Vercel client origin (no trailing slash).
4. Health check path: `/api/health`.
5. After changing `CLIENT_URL`, `JWT_SECRET` or Stripe keys, restart/redeploy the service.

> Keep `JWT_SECRET` identical in the client and server, otherwise every authenticated request is rejected.

## Security notes

- CORS accepts only `CLIENT_URL`.
- JWTs are verified on every protected route; roles come from MongoDB.
- Payment amounts are never trusted from the client.
- There is currently no global rate limiter or security-header middleware; add them before exposing the API to untrusted high-volume traffic.
- Stripe webhook signature verification is not implemented (no webhook endpoint exists).
